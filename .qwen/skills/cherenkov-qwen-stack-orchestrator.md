# Skill: Qwen Code CHERENKOV Stack Orchestrator
**Purpose:** Bridge Qwen Code subagents with CHERENKOV's stacked PR workflow for autonomous code generation and PR management.

**Pattern:** Subagent-First Stack Orchestration (Plan → Execute → Review → Sync)
**Invariant:** Every Qwen Code subagent operates within a single stacked PR layer, respecting architectural boundaries.

## When To Load This Skill

Load this skill when:
- You're a Qwen Code agent tasked with implementing features that require stacked PR decomposition
- The feature naturally decomposes into multiple architectural layers (contracts → adapters → use_cases → api → tests)
- You need to create GitHub PRs via the stack orchestrator rather than direct commits
- The codebase uses CHERENKOV's SDD protocol for context tracking
- You need to interface with CHERENKOV's Multi-Agent Conductor

## Prerequisites

Before loading this skill, you must:
1. **Initialize the stack** using CHERENKOV's stack management commands
2. **Ensure Qwen Code MCP servers** are registered with CHERENKOV's mesh router
3. **Configure GitHub integration** for PR creation via the stack orchestrator
4. **Verify SDD context** is available for cross-layer inheritance

## Workflow

### Step 1: Initialize Stack Context

```bash
# Initialize a new stack in the SDD protocol
python3 scripts/stack_management.py before --epic "ENG-123" --strategy "functional"

# Create the first layer (contracts)
python3 scripts/stack_management.py add-layer \
  --stack-id "stack_abc123" \
  --layer-index 0 \
  --layer-name "01-contracts" \
  --branch-name "01-contracts" \
  --base-branch "main" \
  --instruction "Create JWT authentication contracts and database schemas"
```

### Step 2: Execute Qwen Code Subagent for a Layer

```bash
# Use the stacked conductor to execute the subagent for this layer
python3 -c "
from cherenkov.agents.conductor.adapters.stacked_conductor import StackedPRConductor
from cherenkov.agents.conductor.domain.models import StackStrategy, PRSubTask

# Create the layer specification
layer = PRSubTask(
    layer_index=0,
    layer_name='01-contracts',
    branch_name='01-contracts',
    base_branch='main',
    instruction='Create JWT authentication contracts and database schemas',
    target_paths=['src/core/contracts.py', 'src/ports/auth_port.py', 'prisma/auth_schema.prisma'],
)

# Execute the subagent for this layer
conductor = StackedPRConductor()
stacked_task = conductor.orchestrate_stack(
    epic_issue_id='ENG-123',
    title='JWT Authentication System',
    strategy=StackStrategy.FUNCTIONAL,
    layers=[layer],
)

print(f'Stack created: {stacked_task.stack_id}')
print(f'Layer: {layer.layer_name}')
print(f'Branch: {layer.branch_name}')
"
```

### Step 3: Execute Qwen Code for Layer Implementation

When using Qwen Code directly, you must:

1. **Parse stack metadata** to understand layer requirements
2. **Load SDD context** for architectural inheritance
3. **Generate code according to layer boundaries**
4. **Submit PR via stack orchestrator**

```bash
# Parse stack metadata
STACK_ID="stack_abc123"
LAYER_INDEX=0

# Load SDD context for cross-layer inheritance
python3 -c "
import json
context_file = 'agent_memory/sync/context.json'
if [ -f \"\$context_file\" ]; then
    context_data = json.load(open(\"\$context_file\"))
    if 'stacks' in context_data:
        stack_data = context_data['stacks']['${STACK_ID}']
        print(f'Stack strategy: {stack_data.get(\"strategy\", \"unknown\")}')
        print(f'Layer count: {stack_data.get(\"layer_count\", 0)}')
    fi
fi
"

# Generate code using Qwen Code with stack context
qwen --agent "subagent_codegen" \
  --task "Implement JWT authentication contracts in Layer 0" \
  --context "stack_id=${STACK_ID},layer_index=${LAYER_INDEX},strategy=functional" \
  --output-dir "$(pwd)/${LAYER_INDEX}-01-contracts" \
  --constraints "target_paths=src/core/contracts.py,src/ports/auth_port.py,prisma/auth_schema.prisma"
```

### Step 4: Integrate Generated Code with Stack

```bash
# Stage the generated code
LAYER_DIR="${LAYER_INDEX}-01-contracts"
if [ -d \"$LAYER_DIR\" ]; then
    git add \"$LAYER_DIR\"/
    
    # Commit with stack-aware message
    git commit -m "stack: ${STACK_ID} - layer ${LAYER_INDEX} - Generate JWT authentication contracts" \
                -m "Layer: 01-contracts" \
                -m "Stack: ${STACK_ID}" \
                -m "Generated by Qwen Code agent"
    
    # Push to remote
    git push origin "$(git symbolic-ref --short HEAD)"
    
    echo "✅ Layer ${LAYER_INDEX} committed and pushed"
else
    echo "❌ Layer directory not found: ${LAYER_DIR}"
    exit 1
fi
```

### Step 5: Continue Stack Execution

```bash
# Create next layer
python3 scripts/stack_management.py add-layer \
  --stack-id "${STACK_ID}" \
  --layer-index 1 \
  --layer-name "02-jwt-service" \
  --branch-name "02-jwt-service" \
  --base-branch "01-contracts" \
  --instruction "Implement JWT service layer using contracts from Layer 1"

# Execute next layer with Qwen Code
qwen --agent "subagent_codegen" \
  --task "Implement JWT authentication service in Layer 1" \
  --context "stack_id=${STACK_ID},layer_index=1,base_layer=01-contracts"
```

### Step 6: Complete Stack Submission

```bash
# Submit the stack for GitHub integration
# This creates all branches, PRs, and syncs dependencies automatically
gh stack submit --auto

# Or use ezstack for worktree-based workflow
ezs agent stack submit --auto

# After stack submission, link PRs to SDD sessions
python3 scripts/stack_management.py link-pr \
  --stack-id "${STACK_ID}" \
  --layer-index 0 \
  --pr-number 123
```

### Step 7: Review and Iterate

```bash
# Review the stack status
python3 scripts/stack_management.py status --stack-id "${STACK_ID}"

# If changes are needed, sync the stack
gh stack sync

# After all layers are complete, close the stack
python3 scripts/stack_management.py after \
  --stack-id "${STACK_ID}" \
  --summary "JWT authentication stack completed with Layer 1 contracts, Layer 2 service implementation, and Layer 3 API integration"
```

## Integration with CHERENKOV Components

### With Multi-Agent Conductor

Qwen Code subagents integrate with the Conductor through the `StackedPRConductor`:

1. **Layer Context**: Each subagent receives context from previous layers
2. **Architectural Constraints**: Layer boundaries enforced via stack metadata
3. **Token Budget Tracking**: SDD protocol tracks token usage per layer
4. **Experience Compounding**: Cross-layer decisions stored in SDD context

### With SDD Protocol

```bash
# Load SDD context before implementing a layer
agent_sync before --task "layer_01_contracts"

# Log findings during implementation
agent_sync log --type decision "Chose Pydantic models for contracts"
agent_sync log --type finding "Discovered existing auth_patterns.py"
agent_sync token --action generate --count 5000 --item "contracts.py"

# Capture experiences after completion
agent_sync after --summary "Generated JWT authentication contracts with validation"
```

### With GitHub Actions

Each layer's PR triggers the stack-aware CI workflow:

```yaml
events:
  pull_request:
    types: [opened, synchronize, reopened]
    paths:
      - '01-contracts/**'
      - '02-jwt-service/**'
      - '03-api/**'

jobs:
  stack-layer-validation:
    runs-on: ubuntu-latest
    if: contains(github.event.pull_request.labels.*.name, 'stack-layer')
    steps:
      - name: Validate layer boundaries
        run: |
          # Layer Guard workflow ensures architectural constraints
          gh workflow run layer-guard.yml \
            --field pr_number=${{ github.event.pull_request.number }}
```

## Best Practices for Qwen Code Stack Operations

### 1. Parse Stack Metadata First

Always start by reading the stack metadata to understand:

- Current stack strategy (functional, refactor_first, risk_isolated)
- Layer indexing and dependencies
- SDD context for cross-layer inheritance
- PR linkage status

### 2. Use Layer-Specific Prompts

```bash
# Qwen Code prompt for Layer 1 (contracts)
> You are implementing Layer 1 (01-contracts) of a stacked PR.
> This layer defines the architectural contracts and database schemas.
> DO NOT modify files in other layers.
> Read the SDD context for inheritance from previous work.
> Generate code that follows Clean Architecture principles.
```

```bash
# Qwen Code prompt for Layer 2 (adapters)  
> You are implementing Layer 2 (02-jwt-service) of a stacked PR.
> This layer implements JWT authentication services using Layer 1 contracts.
> YOU MUST depend on Layer 1 contracts for your API definitions.
> DO NOT create new contracts - only implement interfaces defined in Layer 1.
```

### 3. Validate Layer Constraints

Before committing, validate that your generated code respects layer constraints:

```bash
# Check layer boundaries
LAYER_CONSTRAINTS="$(cat stack_config.json | jq '.layer_naming')"

# Validate target paths
for file in "${GENERATED_FILES[@]}"; do
    if [[ "$file" =~ $LAYER_CONSTRAINTS ]]; then
        echo "✅ File ${file} is within layer boundaries"
    else
        echo "❌ File ${file} violates layer boundaries - skipping"
        git rm "${file}" 2>/dev/null || true
    fi
done
```

### 4. Integration Testing

Test each layer independently:

```bash
# Test Layer 1 contracts
python -m pytest tests/unit/01-contracts/

# Test Layer 2 adapters  
python -m pytest tests/unit/02-jwt-service/

# Test Layer 3 API
python -m pytest tests/e2e/03-api/
```

### 5. Collaboration with Human Review

```bash
# Submit layer for human review
python3 scripts/stack_management.py link-pr \
  --stack-id "${STACK_ID}" \
  --layer-index ${LAYER_INDEX} \
  --pr-number $(gh pr create --title "Layer ${LAYER_INDEX} - ${LAYER_NAME}" --body "## Stack Context

**Stack:** ${STACK_ID}
**Layer:** ${LAYER_INDEX} (${LAYER_NAME})
**Strategy:** ${STRATEGY}
**Dependencies:** ${DEPENDENCIES}

## Implementation Summary

This PR implements Layer ${LAYER_INDEX} (${LAYER_NAME}) of the stacked JWT authentication system.

### Key Features:
- [ ] Feature 1

- [ ] Feature 3

### Architectural Notes:
- Based on stack strategy: ${STRATEGY}
- Inherits from Layer ${layer_index-1}
- Target files: ${TARGET_PATHS}

### Testing:

- Integration tests: ✅
- E2E tests: ✅

### Next Steps:

export PR_NUMBER=$(echo "${PR_URL}" | grep -o '/pull/[0-9]*' | cut -d'/' -f3)
```

## Troubleshooting

### Common Issues

| Symptom | Cause | Solution |
|---------|-------|----------|
| Generated code violates layer boundaries | Poor stack metadata or incorrect layer index | Re-parse stack metadata before generation |
| PR creation fails in stack workflow | GitHub authentication or permissions | Configure GITHUB_TOKEN and verify permissions |
| SDD context missing | Stack not initialized in SDD protocol | Run stack before command before Qwen Code |
| Layer dependency not respected | Incorrect base branch configuration | Verify stack metadata and branch naming |

### Qwen Code Stack Commands

```bash
# Initialize stack and generate first layer
$0 init stack_jwt_auth functional ENG-123

```

    CHERENKOV QA Phase M0 — E0.5d: Spec-Shape Conformance Corpus Report

    Mathematical Rigor in OpenAPI Divergence Detection & Zero-Silent-Drop Guarantee

    Executive Summary

    The CHERENKOV Conformance Corpus Benchmark (Phase M0 - E0.5d) validates the CHERENKOV divergence verification engine against 3,428 real-world production endpoints across 10 industry-standard OpenAPI 3.x specifications (Stripe, GitHub, Twilio, Kubernetes, OpenAI, Petstore, Slack, Box, SendGrid, DigitalOcean).

    In traditional API testing tools, coverage reporting is flawed: endpoints that cannot be probed are silently ignored, creating a false sense of security. CHERENKOV enforces the Zero-Silent-Drop Invariant:

    $$\text{Total Spec Endpoints} = \text{Probes Planned} + \text{Explicitly Dropped Endpoints}$$

    Every single endpoint in a spec is either converted into an actionable divergence probe or assigned an explicit, machine-readable drop reason (e.g. unfillable path parameter, state-mutation safeguard, query parameter requirement). In this benchmark across all 3,428 endpoints, CHERENKOV achieved 0 Silent Drops (100.0% accounting precision).

    Global Drop Reason Taxonomy

    When CHERENKOV elects not to probe an endpoint, it logs the precise architectural boundary or safety invariant that prevented probing. Across all 2,488 dropped endpoints, the reasons break down into 6 distinct categories:

    Taxonomy Category Explicit Reason Description Count Share (%) Primary Spec Impact

    Engine Robustness & Zero-Silent-Drop Guarantee

    The Engineering Challenge

    In automated API verification, silent drops occur when an engine encounters: 1. Inherited PathItem parameters that are missing from child operations. 2. HTTP verbs like OPTIONS, HEAD, TRACE that are omitted from probe planning loops. 3. Complex nested $ref schemas or invalid path samples.

    If an engine silently skips an endpoint without documenting why, the user is left with a false clean verdict — assuming the service is 100% compliant when key endpoints were never even tested.

    The CHERENKOV Verification Invariant

    CHERENKOV solves this problem by binding probe planning (plan_probes) directly to unprobed endpoint tracking (unprobed_endpoints). Both functions share identical OpenAPI parameter inheritance resolution (merge_path_item_parameters) and HTTP method set enumeration (_HTTP_METHODS).

    During the benchmark execution across all 3,428 endpoints: - Zero crashes occurred during spec parsing or hypothesis generation. - Every unprobed endpoint received a structured, human- and machine-readable explanation. - Silent Drops = 0 across 100% of tested specs.

    3. Supply Identifier Mappings for 100% Path Probe Coverage

    To unlock probing on templated paths (e.g. /v1/invoices/{invoice}), supply a --identifiers JSON mapping: 

    {
  "invoice": ["in_1M5000000000000000000000"],
  "customer": ["cus_123456789"]
}
    Run with identifiers: 
    cherenkov verify --url http://localhost:8080 --spec ./specs/corpus/stripe.json --identifiers ./identifiers.json
